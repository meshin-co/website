# Capability index

Generated by `npm run assets:spec-index`. One line per capability, taken from its own Purpose.

- [content/collection-schemas](specs/content/collection-schemas/spec.md) — Collection schemas govern the frontmatter each content entry must carry before the site builds: required fields, word and character limits, date order and fixed vocabularies.
- [content/content-gate](specs/content/content-gate/spec.md) — The content gate governs the mechanical rules each gated page must clear in its built HTML, from its one h1 and target query to sentence caps, sourced numbers, profile structure and title alignment.
- [content/human-readability](specs/content/human-readability/spec.md) — Human readability governs how easy the prose on each built page is to read and whether it shows the tells of machine-written text.
- [delivery/link-integrity](specs/delivery/link-integrity/spec.md) — Governs the integrity of the built site's markup and links: valid HTML, links that resolve, no orphaned pages, and the right rel tokens on outbound and internal links.
- [delivery/performance-budgets](specs/delivery/performance-budgets/spec.md) — Governs the byte, search index and Lighthouse budgets that the built site must meet before it ships.
- [design/rendering-and-accessibility](specs/design/rendering-and-accessibility/spec.md) — This capability governs how the built pages look and behave in a real browser: recorded screenshots, zero axe violations in both color schemes, a skip link that takes the first keyboard focus, clean rendering in WebKit and Firefox, and cards that work as one tap target each.
- [discovery/agent-interfaces](specs/discovery/agent-interfaces/spec.md) — What an AI agent finds when it arrives: the terms the site sets for its content, the machine endpoints it can call, and the two documents that catalogue them.
- [discovery/machine-interfaces](specs/discovery/machine-interfaces/spec.md) — Governs the files the site publishes for crawlers, answer engines and feed readers: the llms text files, the markdown sidecars, the RSS and JSON feeds, the sitemap, robots.txt, humans.txt, the canonical URL of every page, the noindex header on machine files and the social cards.
- [discovery/site-search](specs/discovery/site-search/spec.md) — Governs the site's own search: the per-kind index shards the build writes, what each entry holds, how a query is matched and ranked in the browser, and how the `/search` page answers, summarises and recovers from a failed load.
- [discovery/structured-data](specs/discovery/structured-data/spec.md) — Governs the JSON-LD graphs the built pages ship for search engines and answer engines: which route families must carry a graph, which node types each family needs, how `@id` references resolve, and which properties every node a page owns must hold.
- [governance/doc-honesty](specs/governance/doc-honesty/spec.md) — This capability governs the checks that keep the repository's own words honest: citations in tracked documents and project skills must resolve, generated evidence must carry a revision line, and every gate must have a mutation family that shows it failing on a planted bad input, or be listed as owing one.
